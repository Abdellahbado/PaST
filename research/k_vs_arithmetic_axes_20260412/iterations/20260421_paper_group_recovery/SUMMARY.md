Key fixed-`n` findings:

- large-`K` easy unit-contiguous families remain exact via Step 2 through `K=20`;
- dense fastpath improves easy-family runtime for `K>=8`;
- irregular ladders stay exact through `K=6` and first degrade around `K=8`;
- PLAN18 (seeds 0–3) refines this: K=8 is mixed exact/finite-gap; K=10 has no exact rows but still produces finite-gap incumbents; K=12 is mostly timeout/no-incumbent under the current 1200s/12GB budget.
- PLAN19 (K=10/12 redesign) confirms the boundary is structural: exact fixed-block DP is infeasible at K=10/12 under practical budgets (even with guardrails raised to 1e12). Finite-gap incumbents (~0.02-0.06%) at K=10 and timeouts at K=12 are the practical ceiling. Routing override (skip baseline energy_core) is justified for K>=10 hard irregular.
- PLAN22 (adaptive multiplicity) validates that a scoreband + diversity filter (`ambig_scoreband_mult2`) can materially improve gap on the key anchor (hardA_k10 s=0: 0.0172% → 0.0094%) while passing Gate 1. `hybrid_mult2` failed Gate 1 due to K=8 degradation. `early_mult2` passed Gate 1 but only improved runtime. Original decision: promote `ambig_scoreband_mult2` (B).
- PLAN22B (correction pass) ran missing Gate 2 `ambig_scoreband_mult2` rows and showed it does NOT generalize reliably (4-5 vs standard on Gate 2). Mean gap is slightly worse than standard and uniform. **Corrected decision: E** — use `ambig_scoreband_mult2` only as a K=10 quality-improvement candidate, not as a global policy.
- PLAN23 (role-based survivor policy) tested `role_mult3` and `role_mult3_feas` on Gate 1 rows. Both failed Gate 1: only 1 win/1 loss/3 ties vs standard, improved gap on only 1/5 rows, and runtime increased 55-63%. Role-based representatives did not improve stability or gap quality. **Decision remains E** — no survivor-policy change is validated; move next to beam-guided Step 4 certification.
- PLAN24 (beam-guided exact corridor): tested restricting Step 4 exact DP to count vectors near beam's prefix-count trajectory on hardA_k10/hardB_k10 seeds 0-3. Zero corridor pruning in all 24 corridor rows because sparse exact DP skips search (`sparse_skip_theoretical`). Identical gaps to standard. No exact closure, no improvement. K=12 probe skipped. **Decision: D** — no evidence corridor helps on these rows. The blocking issue is the theoretical bound guardrail blocking exact search entry, not state-space pruning inside the corridor.
- PLAN24B (forced-entry corridor diagnostic): tested whether corridor can prune when exact DP is forced to enter via `PAST_EXACT_CORRIDOR_FORCE_ENTRY=1` on hardA_k10 s0, hardB_k10 s2. Force entry bypasses theoretical guardrail but hits `sparse_skip_overflow`: int64 encoding overflows for K=10 at n=1000. Zero states generated, zero pruning. Corridor cannot be tested because encoding is fundamentally limited. **Decision: D** — abandon corridor under current exact DP; int64 encoding is the blocker, not guardrail policy.
- PLAN25 (local offset corridor): implemented a local-offset DP to avoid PLAN24B mixed-radix overflow. Smoke rows on hardA_k10 s0 and hardB_k10 s2 ran memory-safe and avoided overflow, but all local-corridor rows returned `infeasible_corridor` with `best_ub=inf`. Review correction: this is **diagnostic/inconclusive**, not proof that the beam prefix is too close to optimal. The base beam path and block/count alignment must be validated, and corridor-limited UB improvements must not set `lb=ub` without a global proof. Keep disabled by default pending PLAN25B/PLAN26.
- PLAN26 (validate local corridor + multi-idea queue): fixed `lb=ub` bug, added alignment diagnostics, fixed `merged_blocks` propagation, added base-path survival simulation. Phase 1 showed `base_path_survives=0` on all tested local rows with `base_candidate_not_found_at_layer_0`; the planned hardB_k10 s2 delta2 row is missing from the raw artifact. Root cause: beam patterns are generated by work capacity, not schedulability; block-local evaluation is stricter than the beam's global validation. Phase 2/3 cancelled. Phase 4 partially tested existing `ambig_scoreband_mult2`: improved on hardB (2/2) but worsened on hardA (2/2), so promotion fails. Requested new policies `residual_aware` and `late_ambig` were not implemented in this pass. **Decision: C** — local corridor invalid due to block/path mismatch; `ambig_scoreband_mult2` remains a per-instance candidate only.
- PLAN27 (Step-3 adaptive survivor policy): implemented `late_ambig`, `residual_aware`, and `late_residual_ambig` in the beam. Ran Gate A on hardA_k10/hardB_k10 seeds 0-3. `uniform_mult2` passes promotion (6/8 not worse, mean gap 0.0343% vs 0.0345%, runtime -14.3%). `late_ambig` and `late_residual_ambig` show real signal (5W/3L) but fail the 6/8 threshold. `residual_aware` has zero gap effect; blocked by unresolved env-var/read issue where `score_policy` diagnostic stays `default` despite runner setting `PAST_PROFILE_REPAIR_BEAM_SCORE_POLICY=residual_aware`. Family-dependence is clear: `uniform_mult2` helps hardA, `ambig_scoreband_mult2`/`late_ambig` help hardB. **Decision: A with caveat** — `uniform_mult2` is the best validated global Step-3 survivor policy.
